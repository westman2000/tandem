# Исправление личных данных в публичной документации

Дата: 2026-10-11. Исполнитель: Codex. Ветка: `main`. База: `1955bdd`.

## Причина и изменения

После публикации пользователь указал на личный домашний путь в README. Публикация инструкции, привязанной к конкретному компьютеру, была ошибкой. Такой путь также найден в отчёте проверок.

- README теперь описывает клонирование, установку зависимостей, сборку и запуск на macOS/Linux и Windows; готовый бинарный файл не обещается в Git-клоне.
- В отчёте проверок используется `~/.codex` без имени локального пользователя.
- Общие инструкции требуют проверять документацию и Git-имя/email перед публикацией.
- `check:repo` проверяет Markdown, включая блоки кода, на абсолютные домашние пути macOS, Linux и Windows; сообщение ошибки не повторяет найденные личные данные.
- Локальная конфигурация этого репозитория использует публичный GitHub-ник и noreply-адрес для новых коммитов. Глобальная конфигурация не менялась; в новом клоне настройки автора нужно задать отдельно.

## Проверки

- `node --check scripts/check-repo.mjs`, `npm run check:repo` и `git diff --check` прошли.
- В отдельном временном репозитории проверены отклонение путей трёх ОС (оба разделителя Windows), проверка блоков кода, отсутствие личного значения в сообщении ошибки и принятие переносимых путей.
- Проверено содержимое 92 существовавших отслеживаемых файлов: после исправлений домашний путь и личные имя/email из Git в них не найдены. Это адресная проверка известных значений, не полный аудит секретов.
- Код приложения не менялся; Go/UI-тесты и сборки не повторялись.

## Осталось

Новый коммит исправляет текущие файлы, но не удаляет прежнее содержимое и метаданные из 10 ранее опубликованных коммитов. Переписывание опубликованной истории пока не выполнялось: нужно отдельно согласовать замену личных путей и идентификаторов автора/коммитера, изменение хэшей и отправку изменённой истории. Даже такая очистка не удаляет уже сделанные сторонние копии.
