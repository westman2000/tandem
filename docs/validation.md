# Проверка прототипа

## Обновление 0.6: папки проектов (2026-10-11)

- Полный `go test -race ./...` проходит. 13 новых сценариев проверяют создание папки, изоляцию истории и подписок, перенос выбранного проекта из общей базы, сохранение оригинала, независимые копии с одинаковыми историческими ID, перемещение и повторное открытие, lock, будущий формат без изменения БД, импорт внешних правок без потери утверждения, отмену активной генерации при пропаже папки, CSRF и повтор HTTP-действия после миграции. Дополнительные проверки экспорта документа и первого запуска выполнены отдельно с race detector.
- Прототип после переноса сохраняет незакоммиченный код. Тест с настоящим локальным Git и детерминированным агентом подтверждает продолжение по закреплённой копии даже после удаления исходного репозитория. Повреждённое вложение останавливает перенос; исходная регистрация и данные сохраняются, частичная папка распознаётся как незавершённая.
- Ошибка записи Markdown не превращает уже сохранённый ответ в неудачный запрос. Внешняя правка фиксируется новой неутверждённой редакцией, сообщением и событием журнала. Повтор импорта с той же квитанцией не создаёт дубликат.
- `npm test`: 7 Node-тестов и 9 React SSR-тестов проходят. Проверены элементы выбора папки, вывод имени машины/пути, восстановление недоступного проекта, различающиеся адреса независимых копий и нормализация имён. TypeScript/Vite production build проходит.
- `go vet ./...` проходит. Собраны текущий Mac-бинарник и пять CGO-free целей: macOS ARM64/AMD64, Linux ARM64/AMD64, Windows AMD64. Это проверка сборки; запуск на Linux/Windows не выполнялся. Новых зависимостей нет.
- Полный интерактивный сценарий нового диалога в Safari не проверен: среда разработки не позволяет запустить тестовый локальный сервер. HTTP проверен через httptest, интерфейс — SSR/TypeScript. Реальные отключения диска и питания, облачная синхронизация не испытывались; отказы воспроизводились во временных папках. Рабочая `.tandem` пользователя не мигрировалась, запросы к реальным подпискам не отправлялись.

## Обновление 0.4: недоступный участник и независимое ревью (2026-10-11)

- `go test -race ./...`: 37 сценариев с подслучаями проходят; `go vet ./...` без замечаний. Девять новых сценариев проверяют переключение в обе стороны, отказ посреди цикла, сохранение фактического автора и закреплённых моделей, сериализацию запросов одного провайдера, отсутствие повторов известного отказа, ожидание, отключение вручную и недоступность обоих участников.
- Проверены классификация ошибок на границе JSONL/процесса, отсутствие ложного переключения по обычному тексту или некорректному ответу, отсутствие сырого stderr в ошибках. API допускает одиночную работу с одной подпиской, сохраняет отказ второго CLI и запрещает его неавторизованный вызов.
- Документ и прототип завершаются с `self_checked` и долгом независимой проверки. Отдельное ревью выполняет второй агент; при отказе оно не передаётся автору. Возобновление сохраняет документ и историю. Замечания переходят в следующую доработку. Для кода проверено чтение закреплённого Git-коммита, а не несохранённых изменений рабочей папки; оригинальная самопроверка остаётся отдельной записью.
- Production-сборка TypeScript/React и два Node-теста diff проходят. SSR smoke проверяет выбор недоступного агента, отметку самопроверки, возвращение участника, независимую рецензию с пустыми JSON-списками и блокировку действий во время выполнения.
- Пересобраны локальный бинарник и пять CGO-free вариантов для macOS ARM64/AMD64, Linux ARM64/AMD64 и Windows AMD64. Новых зависимостей нет. Выполнение Linux/Windows не проверялось.
- Сценарии отказов используют детерминированный runner и временные CLI-фикстуры; Git и Node-проверка прототипа выполняются реально. Реальные лимиты подписок не расходовали, имитацию отказа не выдаём за проверку серверной ошибки провайдера. Полная проверка интерфейса в Safari не выполнена: инструмент управления приложением вернул `Sky Computer Use native pipe startup failed`. SSR не заменяет браузерную проверку.

Проверено 10 октября 2026 года на macOS ARM64.

## Проверка в браузере

- Chrome: создание проекта; вставка текста как материала; запуск демо; пауза после сохранения черновика; обновление страницы; продолжение до итогового документа.
- Safari: страница загружается и оформляется корректно; подключения обоих CLI отображаются; раздел материалов и форма вставки текста открываются. Полный сценарий ввода завершён в Chrome, чтобы не мешать работе пользователя в Safari.
- Сервер запущен пользователем из обычного терминала. Среда разработки агента не имеет разрешения на сетевое соединение и привязку локального порта.

## Исправление выбора файлов

После сообщения о пропавшем MD-файле в Safari исправлена потеря `FileList`: список копируется синхронно до очистки поля выбора и первого `await`. Пустой выбор больше не вызывает ложное сообщение об успехе. При загрузке видны имя файла и порядковый номер; ошибка указывает файл и количество уже сохранённых материалов.

В отдельной проверке выполнена сама функция загрузки из исходного TypeScript с подменённым API: на предыдущем коде воспроизведены нулевая отправка и ложный успех, на исправленном — сохранение двух MD-файлов с UTF-8 после очистки исходного списка. Также проверены отмена выбора и ошибка второго файла с сохранением первого. Production-сборка и пять переносимых бинарников пересобраны. Повторный полный тест через диалог Safari не выполнен: в активной вкладке пользователь вводил несохранённую идею, её не обновляли.

## Реальные подписки

Проект **«Проверка подписок — таймер»** прошёл полный цикл без демо:

1. Независимые предложения Codex и Claude.
2. Оба агента получили предложение партнёра, обсудили диапазон времени и поведение кнопок.
3. Codex составил черновик.
4. Claude провёл рецензию.
5. Codex выпустил исправленную версию.
6. Claude подтвердил выполнение заданных критериев.

Всего 8 ответов. Состояние `completed`, качество `ready`; документ открыт в браузере, доступна ссылка скачивания Markdown. Результат содержит валидацию минут, состояния таймера, поведение кнопок, звуковой сигнал, три проверяемых критерия приёмки и явные допущения.

Это подтверждает работу установленных версий CLI и текущих подписок на этом компьютере. Другие версии CLI, платформы и корпоративные политики требуют отдельной проверки.
