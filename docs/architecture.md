# Архитектура Tandem 0.4

## Доступность участников и отложенное ревью (0.4)

`AvailabilityPolicy=wait|solo` и `Unavailable[agent]` хранятся в `Run` вместе с причиной и временем отказа. Новая форма предлагает solo; отсутствие поля у старого клиента означает wait. Продолжение и прототип наследуют известные отключения. `/runs/:id/availability` изменяет политику и отключения только вне активного выполнения. `/runs/:id/independent-review` явно разрешает повторный запрос рецензенту после восстановления доступа.

`AgentUnavailableError` отделён от ошибок задания. Классификатор применяется только к error-событиям JSONL и stderr неуспешного процесса; сырой stderr не выдаётся пользователю. Ошибка модели, некорректный JSON, ошибка Git или автотестов не маршрутизирует запрос другому провайдеру. Проверка подписки перед запуском исключает вызов неавторизованного CLI; при solo достаточно одного доступного участника. Проверка входа не проверяет квоту.

Один CLI-провайдер выполняет один запрос одновременно в пределах Engine. Ожидание слота отменяемо; отказ записывается до освобождения слота. После отказа вызывается доступный провайдер, без циклического повтора недоступного. Перенос задачи сохраняет `RequestedAgent`; `Task.Agent` и `Message.Actor` отражают фактического исполнителя, модель закрепляется для него. Перенесённая задача получает свежую CLI-сессию и адресованные исходному исполнителю уточнения. `SelfReview` вычисляется по фактическому автору документа или кода. `quality=self_checked` прекращает цикл по выполненным критериям, оставляя `NeedsReview=true`.

`IndependentReview` ссылается на конкретную задачу документа/плана либо `Build.ID`; исполнителем становится другой агент. Задача `independent_review` возобновляется через обычные pause/resume и recovery. Повтор после недоступности требует явного возвращения участника; на автора проверка не переключается. Для кода контекст читается через `git ls-tree` / `cat-file` из закреплённого коммита, с ограничениями объёма и исключением секретов, symlink и двоичных файлов. Рабочая папка, проверки и старые рецензии не изменяются. Ревью старой версии не снимает долг проверки новой версии. Результат текущей версии меняет качество на ready/review_changes; для плана сохраняется ожидание пользовательского утверждения. Успех рецензии кода учитывает также фактические команды; ручная приёмка остаётся отдельной.

## Компоненты

- **React / TypeScript / Vite:** одностраничный браузерный интерфейс. Production assets встраиваются через `go:embed`. Нет CDN, внешних шрифтов или зависимостей от браузерных расширений.
- **Go HTTP:** локальный API, проверка запросов, загрузка файлов, выдача документов. Клиент опрашивает состояние раз в 1,2 секунды; polling не влияет на выполнение цикла.
- **Engine:** конечный набор стадий, последовательные фазы и параллельные предложения/критика внутри фазы. Одна активная работа в проекте.
- **AgentRunner:** интерфейс, отделяющий жизненный цикл обсуждения от CLI. CLI запускаются через `exec.CommandContext`, без shell-интерполяции. Prompt передаётся через stdin.
- **Store / SQLite:** проекты, циклы, материалы, сообщения, события. WAL и один DB connection, критические изменения Run защищены mutex. На каталог данных берётся межпроцессная блокировка.

## Состояния и контрольные точки

Run: `running → completed`, `running → pausing → paused`, `running → failed`, `paused/failed → running`, `paused/failed → stopped`.

Task: `pending → running → done`. Ответ и сообщение в общем диалоге сохраняются **одной транзакцией**. Повторный `CommitTask` завершённой задачи ничего не добавляет.

При паузе отменяется процесс CLI вместе с группой дочерних процессов на Unix; на Windows используется остановка дерева процессов. Уже завершённые задачи остаются. ID сессий для прерванных задач удаляются, чтобы повторный запрос не продолжал неизвестную частично записанную реплику. Контекст пересобирается из сохранённых материалов и ответов.

На старте `running` и `pausing` переводятся в `paused`. Автоматического повторного расходования подписки после перезапуска нет. ID сессии успешно завершённого агента сохраняется, что позволяет продолжать тот же разговор в рамках цикла.

Это exactly-once сохранение локального результата, **не exactly-once выполнение запроса провайдером**. Если клиент аварийно завершился после того, как провайдер обработал запрос, но до локального commit, повторная попытка может повторно использовать лимит подписки. Tandem честно сообщает о повторном запросе незавершённого ответа.

## Завершение по качеству

Первые фазы: идеи ×2, критика ×2, черновик, рецензия. Затем пары `revision`/`verify`. Проверяющий агент получает критерии, исходные материалы и результаты предыдущих фаз. Последняя строка проверки должна быть `[TANDEM_READY]` либо `[TANDEM_REVISE]`. Только точный READY в последней строке означает готовность по мнению модели.

Лимит — 1–10 проверок, по умолчанию 5. После минимум трёх проверок две последовательные строки `[TANDEM_NO_PROGRESS]` без противоречащего `[TANDEM_PROGRESS]` завершают цикл с `quality=stalled` и `stopReason`. Запасное правило — три одинаковые после нормализации пробелов рецензии и исправленные версии. READY имеет приоритет над остановкой без улучшения. Это оценка модели, возможны ложные срабатывания или пропуск повторяющегося спора.

`POST /api/runs/{id}/continue` принимает `maxRevisions` и `instruction`. Завершённый или вручную остановленный цикл с документом порождает новый Run с `parentRunId`. План начинается с фаз 4/5, далее дополняется обычными парами. Копируются материалы родителя и закреплённые модели, CLI-сессии создаются новые. Prompt включает родительский документ, последнюю рецензию и адресованные уточнения из цепочки доработок. Старые циклы не изменяются.

Если READY нет, следующая пара добавляется в сохранённый план до установленного лимита. Добавление идемпотентно при возобновлении. `quality=limit` не выдаётся за успешно пройденную проверку. Протокол не является объективным доказательством полноты документа: пользователь видит рецензию и принимает решение.

Фазы добавляются последовательно; на экране дополнительные исправления/проверки объединены под последним этапом. Отчёт проверяющего сохранён отдельно от документа, поэтому скачиваемый файл содержит последнюю полную авторскую версию.

## Контекст и файлы

Каждый Run содержит полный снимок извлечённого текста материалов и метаданных. Физические копии оригиналов создаются после проверки хеша. Для независимых предложений в prompt не включаются предложения партнёра. Начиная с критики включаются ответы завершённых предыдущих фаз.

Уточнения пользователя передаются в следующем запросе выбранному агенту. Уже работающий CLI не получает изменения prompt. Это ограничение текущего адаптера; для интерактивного прерывания во время ответа потребуется протокол app-server / streaming input.

Парсеры читают только текстовые ответы и ограниченный набор событий. Сырые JSON-потоки, thinking и reasoning не сохраняются. DOM рендерится React-элементами, без выполнения HTML из ответов.

## Граница первого прототипа

Это координатор обсуждений, не распределённая IDE. В нём нет shell-терминала для пользователя, редактирования внешнего репозитория, общих Git-веток, воркеров по сети или публичного API. Расширение `AgentRunner` позволит позже заменить локальный CLI на аутентифицированный worker, оставив модель задач, контрольных точек и материалов.

До удалённого режима нужны: идентичность workers, TLS, capability scopes, ограничение проектов, доставка с подтверждением, отмена задач, heartbeat и безопасный обмен артефактами. Доступ браузера к локальному однопользовательскому API не следует использовать как этот сетевой протокол.

## Модели

`Run.models` хранит исходный выбор; `Run.lockedModels` — фактические имена после первого ответа. `Task.model` и `Message.model` записываются вместе с ответом в транзакции `CommitTask`. При последующих вызовах закреплённое имя передаётся через `--model`. Несовпадение останавливает цикл с ошибкой; неподтверждённое имя не подменяется запрошенным.

`GET /api/models` возвращает локальные подсказки, а не подтверждение прав аккаунта. Каталоги читаются с ограничением размера, без чтения credential-файлов. Codex не включает имя модели в обычные JSONL-события `exec`, поэтому адаптер читает только поля метаданных точного журнала сессии в `CODEX_HOME/sessions`. Claude сообщает фактическое имя в `assistant.message.model`. Сырые журналы и скрытые рассуждения не переносятся в Tandem. При недоступности метаданных успешный ответ не принимается, чтобы не продолжать с непроверенной моделью.

## План подключаемых CLI-агентов

Статус: запланировано. Следующий новый CLI-адаптер после проверки режима прототипа — Antigravity CLI (`agy`). Обобщение провайдеров начнётся с обсуждения документов на одной машине с двумя участниками. Режим прототипа 0.3 уже поддерживает автора и ревьюера Codex/Claude; одновременная запись кода и удалённые workers идут позже.

### 1. Отделить роли от инструментов

- Ввести участников с устойчивыми ID, ролью («Автор» или «Рецензент»), выбранным CLI и моделью. Каждый из поддерживаемых CLI может выполнять любую роль.
- Заменить привязки к `codex`/`claude` в планировщике, запросах, адресованных уточнениях и интерфейсе реестром адаптеров. Каждый адаптер отвечает за обнаружение CLI, проверку входа, каталог моделей, запуск, разбор событий, продолжение точной сессии и отмену.
- Сохранять состав участников и выбранные модели в цикле; при доработке наследовать их. Существующую историю читать без потери имён, моделей и адресатов сообщений.

### 2. Добавить адаптер Antigravity

- Проверить установленную версию `agy` и необходимые возможности. Использовать официальный вход пользователя через аккаунт и сохранённую CLI-авторизацию; проверить доступные модели и лимиты на реальном аккаунте.
- Передавать задания через stdin, получать `stream-json`, разбирать видимые ответы и итоговый статус. Использовать точный `conversation_id` для продолжения; не подхватывать последний разговор другого проекта.
- Получать список через `agy models`, передавать выбранную модель через `--model`. Отдельно проверить способ подтверждения фактически использованной модели: повторение переданного параметра в `init` само по себе не доказывает фактический выбор. Сохранить правило остановки при неподтверждённой модели или её смене.
- Для обсуждений ограничить доступ к командам и записи файлов средствами CLI, проверить обработку отказов инструментов. Поддержать остановку процесса, таймауты, ошибки входа, исчерпание лимита и повреждённый поток без подмены результата демоответом.

Официальные ориентиры для реализации: [программный запуск и форматы ответов](https://antigravity.google/docs/cli/headless/), [установка и авторизация](https://antigravity.google/docs/cli/install/). При реализации сверить их с установленной версией CLI.

### 3. Критерии готовности

- В браузере выбираются CLI и модель отдельно для автора и рецензента. Доступны пары Codex + Claude, Codex + Antigravity и Claude + Antigravity с перестановкой ролей.
- Обе стороны получают одинаковый снимок материалов и ответы партнёра; адресованные уточнения приходят нужному участнику. Документ, замечания, модели и история сохраняются.
- Работают пауза, восстановление после перезапуска, продолжение доработки, лимит проходов и остановка без улучшения. Сессии разных проектов не смешиваются.
- Проверки адаптера покрывают завершение/обрыв потока, авторизацию, недоступную модель, отмену и отсутствие утечки скрытых рассуждений или учётных данных. Реальный цикл с Antigravity подтверждён на пользовательском аккаунте; существующие сценарии Codex + Claude проходят без регрессий.

## Прототип по утверждённой редакции — версия 0.3

Цель первого прототипа — проверить игровую механику одним законченным игровым циклом. Гипотеза настраивается для других проектов. Платформа продукта и платформа прототипа указываются отдельно: рекомендация по ТЗ, браузер, Android, iOS, Windows, macOS или Linux. Один запуск реализует одну платформу.

Редакции ТЗ доступны отдельно: черновики и исправления всех циклов, сравнение текста, скачивание, явное утверждение пользователем. Прототип получает неизменяемый снимок выбранной редакции с хешем. Изменение ТЗ не меняет действующий план автоматически.

Сценарий: утверждённое ТЗ → предложение автора → замечания ревьюера → итоговый план → проверка инструментов и утверждение пользователем → код → реальные команды проверки → рецензия → запуск пользователем и обратная связь. В плане обязательны гипотеза, границы, упрощения, критерии, способ запуска, команды и необходимые инструменты. Автор и ревьюер выбираются из Codex / Claude Code.

Первая реализация использует существующие подписочные CLI без расширения их разрешений. Автор возвращает структурированные изменения файлов, которые Tandem проверяет и применяет в отдельной Git-копии. Команды проверок из утверждённого плана исполняет Tandem, их stdout/stderr и коды выхода получает ревьюер. Это локальный исполнитель, не контейнерная изоляция команд. Исходный репозиторий не меняется. Новые проекты создаются отдельно; существующие импортируются из локального Git-репозитория с чистым состоянием.

Обязательные журналы: обсуждение, решения и допущения, изменения файлов, команды и реальные результаты. События связаны с циклом/задачей/сборкой, сохраняются в SQLite; выгрузка содержит всю историю, а не только последние события интерфейса. Сборка имеет Git checkpoint, diff, инструкции запуска, ограничения, результат ревью и проверок, отдельную пользовательскую приёмку. Успех сборки не означает проверки на устройстве или интересной механики. Обратная связь и возврат к checkpoint сохраняют прежние сборки.

Ограничения работы: число итераций, суммарное активное время, повторные неудачные проверки и отсутствие изменений. Пауза и перезапуск сохраняют этапы и частичные результаты, прерванная команда отмечается явно. Недоступный инструмент блокирует начало кодинга с понятным сообщением. Удалённые исполнители, одновременная запись двух агентов и новые провайдеры остаются следующими этапами.


Прототип использует `Run.kind=prototype` и состояния `running → awaiting_plan → running → completed`, с общими pause/resume/finish. План сериализуется и закрепляется по SHA-256 при утверждении. Ответы кода содержат полные тексты только изменённых файлов; повторное применение после сбоя не создаёт второй Git-коммит. Внешние изменения рабочей папки не перезаписываются. Для существующего репозитория контекст и исходный commit закрепляются при создании прототипа; изменения исходного репозитория во время обсуждения не подменяют выбранную основу.

Активное время записывается heartbeat каждые 5 секунд; после аварийного завершения учитывается не более одного незаписанного интервала, а время выключенного приложения не расходует весь бюджет. Проверки имеют отдельные попытки и статусы `running/passed/failed/interrupted`; прерванная попытка сохраняется при повторе.

Браузерный preview — неизменяемая копия статических файлов после успешных команд, до 32 МБ / 4000 файлов. Отдельный HTTP listener слушает случайный loopback-порт без API. CSP sandbox без `allow-same-origin` отделяет код прототипа от Tandem; подключение внешних ресурсов ограничено политикой страницы. Исторические preview не берут текущие изменённые файлы. Серверы приложения и устройства запускаются отдельно по инструкции.
