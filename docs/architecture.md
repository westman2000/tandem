# Архитектура Tandem 0.1

## Компоненты

- **React / TypeScript / Vite:** одностраничный браузерный интерфейс. Production assets встраиваются через `go:embed`. Нет CDN, внешних шрифтов или зависимостей от браузерных расширений.
- **Go HTTP:** локальный API, проверка запросов, загрузка файлов, выдача документов. Клиент опрашивает состояние раз в 1,2 секунды; polling не влияет на выполнение цикла.
- **Engine:** конечный набор стадий, последовательные фазы и параллельные предложения/критика внутри фазы. Одна активная работа в проекте.
- **AgentRunner:** интерфейс, отделяющий жизненный цикл обсуждения от CLI. CLI запускаются через `exec.CommandContext`, без shell-интерполяции. Prompt передаётся через stdin.
- **Store / SQLite:** проекты, циклы, материалы, сообщения, события. WAL и один DB connection, критические изменения Run защищены mutex. На каталог данных берётся межпроцессная блокировка.

## Состояния и контрольные точки

Run: `running → completed`, `running → pausing → paused`, `running → failed`, `paused/failed → running`, `paused/failed → stopped`.

Task: `pending → running → done`. Ответ и сообщение в общем диалоге сохраняются **одной транзакцией**. Повторный `CommitTask` завершённой задачи ничего не добавляет.

При паузе отменяется процесс CLI вместе с группой дочерних процессов на Unix; на Windows используется остановка дерева процессов. Уже завершённые задачи остаются. ID сессий для прерванных задач удаляются, чтобы повторный запрос не продолжал неизвестную частично записанную реплику. Контекст пересобирается из сохранённых материалов и ответов.

На старте `running` и `pausing` переводятся в `paused`. Автоматического повторного расходования подписки после перезапуска нет. ID сессии успешно завершённого агента сохраняется, что позволяет продолжать тот же разговор в рамках цикла.

Это exactly-once сохранение локального результата, **не exactly-once выполнение запроса провайдером**. Если клиент аварийно завершился после того, как провайдер обработал запрос, но до локального commit, повторная попытка может повторно использовать лимит подписки. Tandem честно сообщает о повторном запросе незавершённого ответа.

## Завершение по качеству

Первые фазы: идеи ×2, критика ×2, черновик, рецензия. Затем пары `revision`/`verify`. Проверяющий агент получает критерии, исходные материалы и результаты предыдущих фаз. Последняя строка проверки должна быть `[TANDEM_READY]` либо `[TANDEM_REVISE]`. Только точный READY в последней строке означает готовность по мнению модели.

Если READY нет, следующая пара добавляется в сохранённый план до установленного лимита. Добавление идемпотентно при возобновлении. `quality=limit` не выдаётся за успешно пройденную проверку. Протокол не является объективным доказательством полноты документа: пользователь видит рецензию и принимает решение.

Фазы добавляются последовательно; на экране дополнительные исправления/проверки объединены под последним этапом. Отчёт проверяющего сохранён отдельно от документа, поэтому скачиваемый файл содержит последнюю полную авторскую версию.

## Контекст и файлы

Каждый Run содержит полный снимок извлечённого текста материалов и метаданных. Физические копии оригиналов создаются после проверки хеша. Для независимых предложений в prompt не включаются предложения партнёра. Начиная с критики включаются ответы завершённых предыдущих фаз.

Уточнения пользователя передаются в следующем запросе выбранному агенту. Уже работающий CLI не получает изменения prompt. Это ограничение текущего адаптера; для интерактивного прерывания во время ответа потребуется протокол app-server / streaming input.

Парсеры читают только текстовые ответы и ограниченный набор событий. Сырые JSON-потоки, thinking и reasoning не сохраняются. DOM рендерится React-элементами, без выполнения HTML из ответов.

## Граница первого прототипа

Это координатор обсуждений, не распределённая IDE. В нём нет shell-терминала для пользователя, редактирования внешнего репозитория, общих Git-веток, воркеров по сети или публичного API. Расширение `AgentRunner` позволит позже заменить локальный CLI на аутентифицированный worker, оставив модель задач, контрольных точек и материалов.

До удалённого режима нужны: идентичность workers, TLS, capability scopes, ограничение проектов, доставка с подтверждением, отмена задач, heartbeat и безопасный обмен артефактами. Доступ браузера к локальному однопользовательскому API не следует использовать как этот сетевой протокол.
