# Передача разработки между машинами и агентами

## Быстрый вход

Начинайте новую сессию из корня клона `tandem`. Общие правила — [AGENTS](../AGENTS.md), текущая задача — [STATUS](STATUS.md), нужные исходники — [MAP](MAP.md). Достаточно прочитать эти точки входа и относящиеся к задаче файлы. Полный старый чат не требуется.

Проверьте `git status --short --branch` и `git log -5 --oneline`. Запись состояния относится к своей ветке и могла устареть; сверяйте её с кодом и незакоммиченными изменениями. При доступной сети `git fetch origin` обновляет сведения об удалённых ветках без изменения рабочих файлов. Не выполняйте автоматический pull поверх чужой незавершённой работы.

## На новой машине

```sh
git clone git@github.com:westman2000/tandem.git
cd tandem
git status --short --branch
```

Нужны Git, Go версии не ниже `go.mod` и Node.js 22.12+ (CI использует Node 24). Для обычного повторения окружения используйте lock-файлы:

```sh
go mod download
npm ci
npm run check:repo
npm run build
go build -o tandem .
```

На Windows задайте имя `tandem.exe`. Shell-скрипты проекта рассчитаны на sh; можно использовать Git Bash либо запускать перечисленные команды отдельно. CLI Codex/Claude устанавливаются и авторизуются официальным способом на каждой машине; их токены не переносятся через Git. Для проверок репозитория и детерминированных тестов подписки не нужны.

Vite очищает `web/dist/`, включая отслеживаемый `placeholder.txt`. После успешной сборки восстановите только этот файл из HEAD, если сами его не изменяли: `git restore -- web/dist/placeholder.txt`. Это не команда очистки других изменений.

## Правила и навыки

- `AGENTS.md` содержит короткие постоянные правила, без растущего журнала.
- `CLAUDE.md` содержит `@AGENTS.md`: импорт вместо символической ссылки переносится обычными файлами, в том числе на Windows. Новые версии Claude могут читать AGENTS напрямую, но это зависит от режима; импорт оставлен для совместимости. После запуска проверить загрузку в `/context`; настройки организации могут ограничить инструкции.
- Исходник каждого навыка — `.agents/skills/<name>/SKILL.md`. `npm run skills:sync` создаёт идентичные файлы `.claude/skills/<name>/SKILL.md`. Копии входят в Git; новому агенту не нужен запуск генератора, чтобы их обнаружить. `npm run check:repo` проверяет совпадение.
- Навыки: `tandem-verify` — проверки изменений; `tandem-handoff` — восстановление контекста и сохранение прогресса. Их можно вызвать явно либо прочитать соответствующий SKILL.md, если клиент не обнаружил его. Общие навыки/плагины конкретного компьютера проект не копирует.

Ссылки на механизм: [Codex AGENTS](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [Codex skills](https://learn.chatgpt.com/docs/build-skills), [Claude memory/import](https://code.claude.com/docs/en/memory), [Claude skills](https://code.claude.com/docs/en/skills).

## Перед остановкой или передачей

После завершённого этапа, до смены агента/машины или перед длинной рискованной операцией сохраните полезную контрольную точку. Не ждать конца многочасовой сессии.

1. Обновить STATUS: задача и её владелец, ветка, последний проверенный baseline, что готово, что осталось, точная следующая операция и известные ограничения.
2. Для существенной сессии добавить `docs/worklog/YYYY-MM-DD-short-task.md`: запрос, фактический результат, важные решения, команды проверок с исходом, пробелы и передача. Описывать незавершённую работу прямо; не выдавать компиляцию за испытание на устройстве.
3. Проверить изменения и сохранить намеренные файлы коммитом. Для незаконченной задачи — коммит в её ветке с явным `WIP`/checkpoint. Не скрывать необходимую для передачи работу только в локальном stash.
4. Когда отправка авторизована, выполнить обычный push нужной ветки. Для первого сохранения текущего `main`: `git push -u origin main`. Успешная отправка и наличие ветки подтверждают передачу; один локальный commit её не подтверждает.
5. При сбое сети оставить локальный коммит и сообщить ветку/хэш, причину и команду повторной отправки. После восстановления проверить удалённую историю; не использовать force-push для устранения расхождения.

Worklog не обязан содержать хэш собственного будущего коммита. Он может ссылаться на базовый/реализационный коммит; историю самой записи показывает `git log -- <path>`. После внезапного завершения агент сначала изучает `git diff`, состояние репозитория и последнюю запись, затем восстанавливает факты. Инструкции не гарантируют сохранение при выключении питания до записи/коммита.

## Одновременная работа

У каждой независимой задачи — своя ветка и рабочая копия/worktree, явный владелец и ожидаемый результат. На каждой машине свои локальные worktrees; Git переносит ветки, а не живые рабочие папки. В STATUS фиксировать только реальное владение задачей. Назначение через документ не является распределённой блокировкой.

При интеграции сверить общие файлы, выполнить нужные проверки, объединить результаты и переписать STATUS под фактическое состояние целевой ветки. Не выбирать «самую позднюю дату» вместо разрешения смыслового конфликта. Агент-рецензент получает commit/branch, цель и критерии проверки.

## Проверки правил и границы

`npm run check:repo` проверяет наличие входных документов, локальные ссылки Markdown на файлы/папки, согласованность skills, импорт CLAUDE, отсутствие абсолютных домашних путей в Markdown (включая блоки кода) и отслеживаемых служебных данных/секретных файлов по именам. Это не сканер всех секретов и не оценка актуальности текста. Перед публикацией отдельно проверяйте diff и Git-имя/email автора и коммитера: используйте публичный ник и noreply-адрес. Метаданные старых коммитов требуют отдельной проверки истории; обычный новый коммит их не удаляет.

[GitHub Actions](../.github/workflows/checks.yml) запускает проверку репозитория и тесты приложения после push/PR, если Actions разрешён в репозитории. Удалённый запуск для `6cce369` [успешно завершён](https://github.com/westman2000/tandem/actions/runs/38184936719); для новой контрольной точки проверяйте её собственный запуск. Чтобы не допускать слияние при красных проверках, можно сделать их обязательными в настройках ветки; такие настройки пока не включены.

Пользовательские базы, материалы, личные конфиги, `.env`, токены, машинные кеши и полные CLI-логи не входят в Git. Для проектов внутри Tandem нужна отдельная резервная копия всей папки после остановки приложения; копия исходников приложения не сохраняет их историю.

## Перенос пользовательского проекта

Разработку самого Tandem можно продолжить из клона GitHub. Для проекта, созданного внутри приложения, отдельно перенесите его данные:

1. Остановите Tandem на исходной машине. Закрыть вкладку браузера недостаточно.
2. Для самостоятельного проекта скопируйте всю папку с `tandem.project.json`, включая скрытую `.tandem/`, документы, материалы, код и скрытые Git-каталоги прототипов. На новой машине запустите Tandem и используйте «Открыть папку проекта».
3. Если проект ещё хранится в прежней общей `.tandem/`, сначала используйте перенос в отдельную папку в интерфейсе. Для резервной копии прежнего хранилища сохраняйте всю `.tandem/` после остановки приложения; один файл SQLite не включает вложения и код. Не считайте копирование общей базы полноценным переносом путей на другую машину.
4. На новой машине установите нужные инструменты и войдите в официальные CLI. Восстановите зависимости прототипа по его инструкции; перед продолжением проверьте доступность папки и сохранённое состояние. Незавершённая работа требует явного продолжения.

Не переносите живую SQLite через синхронизацию облачной папки и не открывайте один проект одновременно на двух машинах. Неотправленные черновики браузера сохраняются только в исходном браузере; перед переносом сохраните нужный текст в проект. Пользовательские материалы не публикуются вместе с исходниками Tandem.

## Готовое начало следующего разговора

> Продолжи разработку Tandem в этом репозитории. Прочитай AGENTS.md и docs/STATUS.md, проверь ветку, последние коммиты и незакоммиченные изменения. По docs/MAP.md найди нужные файлы. Если новой задачи от меня нет, начни со следующего конкретного шага в STATUS. Сохраняй существенные результаты по docs/HANDOFF.md; перечисли то, что не удалось проверить. Пользовательские проекты и их историю не публикуй в репозиторий приложения.
